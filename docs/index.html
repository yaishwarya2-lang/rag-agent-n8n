The problem

Most teams do not have knowledge problem. They have "where did we put that?" problem

What I built

I built a Brewlight Agent. You might be thinking what's a Brewlight Agent? Its a RAG chatbot that answers questions from company's database instead of guessing. It is built in two Parts: Ingestion Workflow: It fetches the company's PDF from google drive and split it into chunks, followed by this the embedding is further carried out with the help of Gemini and stored in Pinecone.
In Second Phase: A chat agent is built which checks the knowledgebase before answering and this memory search is not simple its a vector search which is being performed with help of Pinecone. Built with n8n, Pinecone, and Google Gemini

IngestionDrive → chunks → embeddings → Pinecone
RetrievalAgent calls the vector store as a tool
MemoryFollow-up questions keep context

Decisions I made

Same embedding model on both sides. I used Gemini embeddings both while loading the document and while searching it. If kept different then that would affect the search and that could cause the search to stop working, so I kept them identical.

Keeping ingestion and search in sync. Initially, it returned nothing, post investigation found that the document was stored in one Pinecone namespace while it was looking for other. Now, both use the same index and namespace, and I checked that first whenever answers look wrong.

Honest "I don't know" over a confident guess. I aksed the agent to answer only from what it retreives.For a company assistant a wrong answer may lead to a disaster, rather than no answer.

What I’d do next

Right now I test the agent by asking it a few questions and seeing if the answers feel right. Next, I want to write down a set of real questions with the correct answers, so I can see exactly how often it gets them right every time I change something.

Core Concepts covered in this Project

Large language model (LLM): The Gemini chat model that reads the question and writes the answer
RAG (retrieval-augmented generation): The whole pipeline: retrieve relevant text first, then generate an answer from it
Embeddings Gemini Embeddings: turn text into vectors that capture meaning
Vector database Pinecone: stores the vectors and finds the closest ones to a question
Semantic search: Finding chunks by meaning, not exact keywords, so “time off” can match “annual leave”
Chunking: The Recursive Character Text Splitter cuts documents into smaller pieces
AI agent: BrewlightAgent decides whether to search and how to answer
Tool use (function calling): The Pinecone vector store is a tool the agent can choose to call
Memory / context: Simple Memory keeps earlier turns so follow-up questions work
System prompt: The instructions that gave the agent its role and its “answer only from the handbook” rule
